# Ответы бэкенда на чек-лист BACKEND_INTEGRATION.md

Фронт уже подключён к настоящим данным NASA. Сайт остаётся **полностью статическим**: отдельного сервера нет.

**Что лежит в `public/data/v1/`:**
- `cells.json`
- `meta.json`
- `oblast.geojson`
- `districts.geojson`

**Как обновить данные:** после пересборки бэкенда достаточно одной команды:

```
cd ../backend && .venv/bin/python scripts/35_export_frontend.py --sync
```

## Чек-лист

**1. Базовый URL и пути.**
- В `.env.production` задано `VITE_API_URL=/data/v1`, поэтому `npm run build` собирает сайт на реальных данных.
- Файлы:
  - `/data/v1/meta.json` (контракт 4.1);
  - `/data/v1/cells.json` (контракт 4.2);
  - `/data/v1/oblast.geojson` и `/data/v1/districts.geojson` (контракт 4.4).
- Без `VITE_API_URL` (`npm run dev`, vitest) фронт работает на моке.
- **Внимание:** `npm run e2e:build` теперь тоже собирает реальные данные. e2e-тесты ждут демо-ответов, поэтому их нужно запускать на моке, например `VITE_API_URL= vite build`, или переписать под фикстуру.

**2. Сетка.** Совпадает с разделом 3: 40 × 22 ячейки по 0,12° × 0,09°, начало в точке lon 73,6, lat 42,55, id `"c,r"`. В `meta.grid` параметры продублированы.
- Внутри бэкенд считает на родной сетке MODIS 1 км, а ячейки 10 км собирает из ячеек 1 км.
- В выгрузке 447 ячеек: 439 пастбищ, 8 исключённых, 0 «мало данных».
- По районам: NA 83, AT 146, JU 66, KO 73, AK 64, SU 15. Ячейки Суусамыра есть только там, где их покрывает наш куб.

**3. Ряды NDVI.** Отдаются вместе с ячейками, в поле `series` (26 чисел за 2000–2025).
- Это **среднее за лето (май–сентябрь)** NDVI MOD13A3 по пастбищным квадратам 1 км внутри ячейки, а не пик за июнь–август. Подписи на фронте уже исправлены.

**4. Пропуски.** Вариант (а): пропуски заполнены линейной интерполяцией.
- `seasons` — честное среднее число лет, где было хотя бы 3 ясных месяца из 5. `cov` = `seasons / 26`.
- В реальных данных пропусков почти нет (MOD13A3 — месячные композиты). Поэтому ячеек `Low` и `nodata` сейчас нет, и это честный результат.

**5. Правила полей.** Где они отличаются от таблицы 4.2, так сделано сознательно, по PRD:
- **`pct` и `level`:** это балл уровня TrendeX, а не одна зелень. В балл входят четыре компоненты: зелень 0,4, стабильность по годам 0,2, длина сезона 0,2 и рельеф 0,2. Каждая сначала переводится в перцентиль на 1 км. Балл усредняется по пастбищу ячейки, ранжируется среди всех пастбищных ячеек (Нарын + Суусамыр), а `level` — это трети этого ранга. В ячейке также есть поле `score` (0–100).
- **`slope`:** наклон Тейла–Сена, % от среднего в год, с округлением до 0,1.
- **`trend`:** надёжный, если p-значение теста Манна–Кендалла с поправкой Хамеда–Рао на автокорреляцию проходит FDR Бенджамини–Хохберга (q < 0,05) по всем пастбищным ячейкам и при этом `seasons` ≥ 16. Получилось 4 `dec`, 41 `inc` и 394 `nr`. В ячейке есть поля `p_value` и `q_value`.
- **`strong`:** как в таблице, надёжный тренд и |slope| ≥ 1,1 %/год. Таких сейчас 3.
- **`conf`:**
  - `Low`, если `cov` < 0,6;
  - `High`, если тренд надёжный, `cov` > 0,78 и уровень **не меняется при других весах** (проверка чувствительности из PRD);
  - иначе `Medium`.
- **`kind`:** `pasture`, если пастбищные квадраты 1 км покрывают не меньше половины ячейки.
  - Пастбище — всё, кроме воды, снега и льда, застройки, пашни, леса (MCD12Q1 2020) и склонов круче 35° (NASADEM).
  - «Голая земля» MCD12Q1 (класс 16) считается пастбищем с низким уровнем, а не исключается.
  - Поэтому фраза в карточке «grassland covers less than half» верна лишь приблизительно. Если нужно, поправьте её на «pasture land covers less than half».

**6. `landCover`.** Есть у каждой ячейки: grassland, cropland, settlement, water, bare, forest (доли 0–1 по MCD12Q1). Карточка исключённой зоны уже собирает строку детализации из этих долей (`landCoverDetail` в `answer.ts`). Заглушки ESA WorldCover используются только на моке.

**7. Тексты `why`.** На английском, в формате таблицы 4.3:
- `Water: Lake Son-Kul`
- `Water: Lake Chatyr-Kul`
- `Glacier, snow and bare rock`
- `Glacier, snow and steep bare rock`
- `Irrigated cropland and settlement`
- `Settlement and cropland`
- `Forest`
- для `nodata`: `Snow or cloud in most seasons`

**8. Общая очередь (4.5) и проверки (4.6).** Пока не нужны: очередь остаётся в localStorage, сервера нет. Ожидания для проверок команда пишет в `backend/configs/known_places.yaml`; полевых наблюдений пока нет.

**9. Тейл–Сен для контуров.** Не нужен: OLS по среднему ряду для нарисованного контура оставлен. На странице Methods (production-вариант) написано, что тренды ячеек считаются через Тейла–Сена и Манна–Кендалла, а контуры — через OLS. Если понадобится, в `web-api/trendex-api.mjs` уже есть порт Тейла–Сена и Манна–Кендалла, его можно использовать в браузере.

**10. CORS, HTTPS, авторизация.** Сервера нет, данные отдаются тем же статическим хостингом (Vercel). CORS не нужен, HTTPS обеспечивает Vercel, авторизации нет. `vercel.json` уже исключает `/data/` из rewrite.

**11. Пример ответа.** Реальный `public/data/v1/cells.json` (447 ячеек, 252 КБ). В нём есть пастбища, вода и ледник. Ячеек `nodata` в реальных данных нет.

## Что поменяно во фронте

- `src/data/source.ts`:
  - добавлен `apiSource`: `meta.json`, `cells.json` и границы из `/data/v1`;
  - маска строится из `d`;
  - `demo`, `low` и `excl` берутся из `meta`;
  - источник выбирается так: `source = VITE_API_URL ? apiSource : mockSource`.
- Новый файл `src/data/info.ts`: `dataStatus`, версия пайплайна и источники из `meta`.
- `src/lib/types.ts`: в `Cell` добавлены необязательные поля `series`, `landCover`, `score`, `p_value` и `q_value`.
- `src/lib/series.ts`: функция `series()` возвращает настоящий ряд ячейки, если он есть. Поэтому `answer.ts` и `trends.ts` не менялись.
- `src/store.ts` и `src/App.tsx`: добавлены поля состояния `real` и `loadError` и экран «Could not load data» с кнопкой «Try again».
- Подпись «Sample data» и тексты про выборочные данные скрываются, когда `dataStatus = production`. Это касается:
  - TopBar;
  - подписи графика в карточке;
  - страниц Trends и Queue;
  - заголовков CSV;
  - страницы Methods: описание метода, таблица источников NASA, версия пайплайна, раскрытие использования AI.
- `src/lib/answer.ts`: детализация исключённой зоны собирается из `landCover`.
- `.env.production`: `VITE_API_URL=/data/v1`.

**Проверки:** `npm run typecheck` проходит, vitest 40/40 (на моке), `npm run build` проходит. Production-сборку проверил в браузере на 1440 × 900: карта, карточка, Trends, Queue, Methods и карточка исключённой зоны. Ошибок в консоли нет. Playwright-тесты не запускал: они рассчитаны на мок.
