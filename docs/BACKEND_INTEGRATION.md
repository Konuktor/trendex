# TrendeX: подключение фронтенда к бэкенду

Документ для бэкенд-разработчика. Бэкенд уже готов; здесь описано, **какие данные ждёт фронтенд, в каком виде, что он считает сам и какие файлы во фронте нужно поменять**, чтобы вместо выборочных (sample) данных пошли настоящие.

Репозиторий: `Downloads/trendex`, ветка `feat/trendex-frontend`. Стек: React 18 + TypeScript + Vite, статическая сборка (Vercel). Своего сервера у фронта нет — всё берётся по HTTP с вашего API.

---

## 1. Коротко

1. Фронту нужен **один основной запрос**: список всех ячеек сетки исследования (≈500 штук) с их показателями **и рядом NDVI за 26 сезонов** (2000–2025).
2. Всё остальное (зоны на карте, ответ в карточке, «лучше рядом», очередь, доли, графики) фронт считает **сам** из этих ячеек.
3. Единственная точка подключения — `src/data/source.ts`. Сейчас там мок, нужно добавить реализацию, которая ходит в API.
4. Сетка, коды районов, единицы и правила классов должны совпадать с описанными ниже — иначе фронт покажет неверные ответы, не упав.

---

## 2. Как фронт получает данные сейчас

```
App start
  └─ store.load()                               src/store.ts
       └─ source.getCells()                      src/data/source.ts   ← ТОЧКА ЗАМЕНЫ
            ├─ fetch /data/kgz-adm1.geojson      (границы областей, статика в public/)
            ├─ fetch /data/kgz-adm2.geojson      (границы районов, статика в public/)
            ├─ buildMask(adm1, adm2)             какие ячейки входят в зону исследования
            └─ buildData(mask)                   МОК: генерирует показатели ячеек
                 → { data: DataSet, mask: StudyMask }

Дальше всё на фронте:
  answer.ts  — карточка ответа (берёт ряды через series(cell) — тоже МОК)
  trends.ts  — страница Trends (тоже series(cell))
  zones.ts, queue.ts, stats.ts, checks.ts — из полей ячеек
```

Ряды NDVI сейчас генерирует функция `series(cell)` из `src/lib/series.ts`; она вызывается в двух местах:
- `src/lib/answer.ts:199` — средний ряд выбранной зоны или контура;
- `src/lib/trends.ts:21` — средний ряд области или района.

Эти два вызова нужно перевести на настоящие ряды (см. раздел 6).

## 3. Сетка и идентификаторы (должны совпадать)

| Параметр | Значение | Где во фронте |
|---|---|---|
| Размер сетки | 40 столбцов × 22 строки | `src/lib/geo.ts` (`COLS`, `ROWS`) |
| Размер ячейки | 0,12° долготы × 0,09° широты (≈10 × 10 км, 100 км²) | `DLON`, `DLAT`, `CELL_KM2` |
| Начало (левый верхний угол) | lon 73,6, lat 42,55 | `LON0`, `LAT0` |
| Центр ячейки `(c, r)` | `lon = 73.6 + (c + 0.5) * 0.12`, `lat = 42.55 − (r + 0.5) * 0.09` | `cellCenter()` |
| Id ячейки | строка `"c,r"`, например `"3,4"` (без пробелов) | везде |
| Годы ряда | 2000…2025, ровно 26 значений, по порядку | `YEARS`, `FIRST_YEAR` в `src/lib/noise.ts` |

**Если у вас другая сетка** (другой шаг или начало), нужно либо пересчитать её под эти параметры, либо отдавать параметры сетки в `/meta` (раздел 4.1), а фронт поправить так, чтобы он брал их оттуда, а не из констант. Скажите заранее, какой вариант.

## 4. Предлагаемый контракт API

Названия путей — предложение; если у вас уже есть свои, сообщите, и фронт подстроится. Важны **поля и их смысл**.

Базовый URL фронт будет брать из переменной окружения `VITE_API_URL` (например `https://api.example.kg/trendex/v1`).

### 4.1 `GET /meta` — один раз при загрузке

```json
{
  "dataStatus": "production",
  "pipelineVersion": "1.0.0",
  "generatedAt": "2026-10-01T00:00:00Z",
  "years": [2000, 2025],
  "grid": { "cols": 40, "rows": 22, "lon0": 73.6, "lat0": 42.55, "dlon": 0.12, "dlat": 0.09 },
  "sources": {
    "ndvi": "MODIS MOD13Q1 C6.1",
    "landCover": "ESA WorldCover v200",
    "precip": "CHIRPS v2.0",
    "dem": "Copernicus DEM GLO-30",
    "boundaries": "geoBoundaries gbOpen KGZ"
  }
}
```

- `dataStatus`: `"sample"` или `"production"`. Фронт по нему решает, показывать ли плашку «Sample data» (см. раздел 6.4).
- `pipelineVersion` идёт в таблицу источников на странице Methods.

Можно вшить это в ответ `/cells` вместо отдельного запроса.

### 4.2 `GET /cells` — главный запрос

Возвращает **все ячейки зоны исследования**: пастбища, исключённые (вода, посёлки, ледники) и «мало данных». Ячейки вне зоны исследования не нужны.

```json
{
  "cells": [
    {
      "id": "3,4",
      "c": 3,
      "r": 4,
      "lon": 74.02,
      "lat": 42.145,
      "d": "SU",
      "kind": "pasture",
      "why": "",
      "water": false,
      "pct": 51,
      "level": "moderate",
      "slope": -1.1,
      "trend": "dec",
      "strong": true,
      "cov": 0.9,
      "seasons": 23,
      "conf": "High",
      "series": [0.512, 0.498, 0.505, "…всего 26 чисел…", 0.382]
    }
  ]
}
```

Объём: ≈500 ячеек × 26 чисел ≈ 13 000 значений, 100–150 КБ JSON (до 30–40 КБ в gzip). Это нормально для одного запроса, отдельный запрос рядов не обязателен.

#### Поля ячейки

| Поле | Тип | Смысл и правила |
|---|---|---|
| `id` | string | `"c,r"`, см. раздел 3. Должен совпадать с `c` и `r`. |
| `c`, `r` | int | Столбец 0…39, строка 0…21. |
| `lon`, `lat` | number | Центр ячейки (формула из раздела 3). |
| `d` | enum | Район: `NA` Нарын, `AT` Ат-Башы, `JU` Жумгал, `KO` Кочкор, `AK` Ак-Талаа, `SU` Суусамырская долина (ячейки Чуйской области: lon < 74,7 и 41,95 < lat < 42,32). |
| `kind` | enum | `pasture` — пастбище; `excluded` — не пастбище (вода, посёлок, пашня, ледник, скалы); `nodata` — мало ясных сезонов. |
| `why` | string | Причина для `excluded` и `nodata`; у пастбищ пустая строка. **Текст важен**, см. 4.3. |
| `water` | bool | `true` для озёр (Сон-Куль, Чатыр-Куль). Такие ячейки исключены и **не рисуются** на карте. |
| `pct` | int 0…100 | Перцентиль средней пиковой зелени среди **всех пастбищных** ячеек (Нарынская область + Суусамыр). |
| `level` | enum | `low` / `moderate` / `good` — нижняя, средняя, верхняя треть по `pct`. |
| `slope` | number | Наклон тренда в **% от среднего за год**, округлён до 0,1 (например `-1.1`). |
| `trend` | enum | `dec` — надёжное снижение, `inc` — надёжный рост, `nr` — нет надёжного тренда. Надёжный = Mann–Kendall p < 0,05 **и** ≥ 16 из 26 ясных сезонов. |
| `strong` | bool | `true`, если тренд надёжный и \|slope\| ≥ 1,1 %/год (на карте — тёмный цвет). Для `nr` всегда `false`. |
| `cov` | number 0…1 | Доля ясных сезонов = `seasons / 26`. Фронт использует порог **0,6** (меньше — низкая уверенность). |
| `seasons` | int 0…26 | Число ясных сезонов июнь–август. |
| `conf` | enum | `High` / `Medium` / `Low`. Правила: `Low`, если `cov < 0.6`; `High`, если тренд надёжный и `cov > 0.78`; иначе `Medium`. |
| `series` | number[26] | Пиковый NDVI (макс. ясных наблюдений июнь–август) за 2000…2025 по порядку. Единицы — NDVI (≈0,2…0,7). |

Для `excluded` и `nodata` поля `pct`, `level`, `slope`, `trend`, `strong`, `conf` фронт не показывает; заполните любыми допустимыми значениями (например `level: "low"`, `trend: "nr"`, `slope: 0`), но **не `null`** — иначе нужна доработка типов. `series` для них можно отдать пустым массивом.

#### Пропуски в рядах

Сейчас фронт **не умеет** работать с `null` внутри `series`: ему нужно ровно 26 чисел. Варианты:
- (а) бэкенд отдаёт ряд уже с заполненными пропусками (интерполяция), а `seasons`/`cov` честно отражают реальное число ясных лет; **или**
- (б) бэкенд отдаёт `null` для пропущенных лет, а фронт дорабатывается (среднее, наклон и шкала «This season» будут игнорировать пропуски).

Сообщите, какой вариант у вас; по умолчанию фронт рассчитан на (а).

### 4.3 Тексты причин (`why`) — от них зависит карточка

Карточка исключённой зоны выбирает строку детализации **по началу текста `why`** (`src/lib/answer.ts`):

| `why` начинается с | Что покажет карточка в детализации |
|---|---|
| `Water: ` (например `Water: Lake Son-Kul`) | «Open water covers most of the zone (ESA WorldCover 2021)», серый образец воды |
| `Glacier` | «Snow, ice and bare rock cover 83% of the zone» |
| `Irrigated` | «Cropland 58%, settlement 21%, grassland 17% (ESA WorldCover 2021)» |
| всё остальное | «Settlement 34%, cropland 41%, grassland 22% (ESA WorldCover 2021)» |

Эти проценты — **заглушки из прототипа**. Для настоящих данных лучше добавить в ячейку поле:

```json
"landCover": { "grassland": 0.17, "cropland": 0.58, "settlement": 0.21, "water": 0.0, "bare": 0.04 }
```

Фронт тогда соберёт строку детализации из реальных долей (зоны усредняются по ячейкам). Если такого поля не будет, оставьте тексты `why` в формате из таблицы.

Для `nodata` используется `why = "Snow or cloud in most seasons"` (или ваш текст) и `seasons` (фронт пишет «Only N of 26 seasons had clear June–August observations»).

Тексты интерфейса на английском. Если `why` будет на русском или кыргызском, карточка покажет его как есть, но выбор детализации по таблице выше перестанет работать — тогда нужен `landCover`.

### 4.4 Границы — `public/data/*.geojson` (можно не трогать)

Фронт берёт границы области и районов из статических файлов `public/data/kgz-adm1.geojson` и `kgz-adm2.geojson` (geoBoundaries). Они используются для:
- рисования границы области и пунктира районов;
- определения района ячейки и маски (только в моке).

С настоящим API маску и район присылаете вы (`d` в каждой ячейке), а файлы остаются только для отрисовки границ. Если у вас свои, более точные границы, отдайте их по `GET /boundaries/oblast` и `GET /boundaries/districts` (GeoJSON FeatureCollection, WGS84, `properties.shapeName`), и фронт возьмёт их оттуда.

### 4.5 Очередь проверок (необязательно)

Сейчас «Add to queue» сохраняет области **в localStorage браузера** (ключ `trendex.queue.v1`). Если очередь должна быть общей для команды, нужны:

| Метод | Путь | Тело / ответ |
|---|---|---|
| `GET` | `/queue` | `[{ key, type: "zone" \| "drawn", cellId?, poly?, name, flag?, addedAt }]` |
| `POST` | `/queue` | один элемент того же вида |
| `DELETE` | `/queue/{key}` | — |

`key` — id ячейки-якоря зоны (`"3,4"`) или `"drawn:<координаты>"`; `poly` — массив `[lon, lat]`; `flag: true` — «проверить маску» (для исключённых зон); `addedAt` — миллисекунды Unix. Ранжирование очереди фронт считает сам.

Если общая очередь не нужна, ничего делать не надо.

### 4.6 Проверки на странице Methods (необязательно)

Таблица «Checks» (известные места: ожидание и наблюдение) сейчас описана во фронте (`src/lib/checks.ts`), «ожидания» там условные. Если у вас есть полевые наблюдения от районных пастбищных комитетов, отдайте их:

```json
GET /checks
[{ "place": "Kochkor village", "lon": 75.755, "lat": 42.215, "expected": "Excluded: cropland and settlement",
   "test": { "kind": "excluded" } }]
```

`test` — одно из: `{ "kind": "excluded" }`, `{ "trend": "dec"|"inc"|"nr" }`, `{ "level": "low"|"moderate"|"good" }`, `{ "conf": "Low" }`. «Наблюдение» и совпадение фронт посчитает сам.

## 5. Что фронт считает сам (бэкенду не нужно)

| Что | Где | Из каких полей |
|---|---|---|
| Сглаженные зоны на карте (контуры d3-contour) | `src/lib/zones.ts` | `c`, `r`, `kind`, `water`, `level`, `trend`, `strong`, `cov` |
| Выбор зоны по клику (та же категория, соседи по стороне, не дальше 2,3 ячейки) | `zoneOf` | то же |
| Карточка ответа: уровень, тренд, уверенность, «Why», «This season», «Better nearby», следующий шаг | `src/lib/answer.ts` | все поля + `series` |
| Ответ по нарисованному контуру (средний ряд ячеек внутри, свой наклон и интервал) | `answer.ts` → `fit()` | `series`, `cov` |
| Доли «надёжное снижение / рост / ненадёжно», матрица уровень × тренд, районы | `src/lib/stats.ts`, `trends.ts` | `trend`, `level`, `d` |
| График области или района и наклон среднего | `trends.ts` | `series` |
| Ранжирование очереди: крутизна снижения × вес уровня (low 1,3 / moderate 1,0 / good 0,7) × вес уверенности (High 1,0 / Medium 0,8) | `src/lib/queue.ts` | `slope`, `level`, `conf` |
| Названия мест («Around Suusamyr», «Kochkor, 15 km SW») и поиск | `src/lib/places.ts` | список сёл зашит во фронте |
| CSV-выгрузки | `trends.ts`, `queue.ts` | поля ячеек |

Важно: наклон для **нарисованного контура** и для **среднего области** фронт считает **обычной регрессией (OLS)** по среднему ряду, с интервалом 95 %. Наклоны **ячеек** берутся от вас как есть (у вас — Theil–Sen + Mann–Kendall). Если хотите, чтобы и контуры считались Theil–Sen, понадобится эндпоинт `POST /aggregate` (тело — список id ячеек, ответ — `slope`, `lo`, `hi`, `trend`) или порт алгоритма во фронт. Сообщите, нужно ли.

## 6. Что поменять во фронте

Это работа фронтенда (сделаю я или фронтендер), но бэкендеру полезно знать объём.

### 6.1 Новый источник данных

`src/data/source.ts`: добавить `apiSource`, который делает `GET {VITE_API_URL}/cells` (+ `/meta`), собирает `DataSet` (`cells`, `past` = пастбищные ячейки, `byId`) и `StudyMask` (границы из `public/data`, `m` из `d` ячеек), и переключить:

```ts

```

Без `VITE_API_URL` фронт продолжит работать на моке — удобно для разработки интерфейса.

Поля `demo`, `low`, `excl` в `DataSet` — это демо-ячейки прототипа (Суусамыр, Ак-Сай, Кочкор). С настоящими данными: `demo` — ячейка, выбранная по умолчанию при открытии карты (можно отдавать в `/meta` как `defaultCellId` или оставить `"3,4"`); `low` и `excl` используются только для скриншот-состояний `?state=lowConfidence|excluded` и для демо-тура.

### 6.2 Ряды из ответа вместо генератора

- В тип `Cell` (`src/lib/types.ts`) добавить `series: number[]`.
- В `src/lib/answer.ts` и `src/lib/trends.ts` заменить `series(cell)` на `cell.series`.
- Генератор `series()` останется только в моке.

### 6.3 Ошибка загрузки

Сейчас есть состояние загрузки (серые заглушки), но **нет экрана ошибки**: если API недоступен, будет вечная загрузка. Нужно добавить сообщение «Could not load data» с кнопкой «Try again».

### 6.4 Метка «Sample data»

По `meta.dataStatus === "production"` убрать или заменить подписи о выборочных данных:
- плашка в верхней панели — `src/components/TopBar.tsx`;
- подпись графика в карточке — `src/components/card/AnswerCard.tsx`;
- подзаголовки и подписи — `src/routes/TrendsRoute.tsx`, `src/routes/QueueRoute.tsx`;
- первая строка CSV `# … sample data …` — `src/lib/trends.ts`, `src/lib/queue.ts`;
- раздел Methods про OLS как временную замену Theil–Sen, версия пайплайна `0.1.0 (sample data)`, текст «All pasture figures in this pilot are sample data» — `src/routes/MethodsRoute.tsx`.

### 6.5 Тесты

- Тест паритета `src/lib/parity.test.ts` сверяет мок с прототипом. Он остаётся, но проверяет только мок.
- e2e-тесты Playwright ждут конкретных ответов демо-данных («Around Suusamyr», «High confidence», «Only 13 of 26 seasons»). На реальных данных их нужно запускать **на моке** (без `VITE_API_URL`) или переписать под ваши тестовые данные. Удобно, если у вас будет стабильный тестовый набор (фикстура `/cells` в репозитории) для CI.

## 7. Нефункциональные требования к API

- **CORS**: разрешить источник фронта (localhost:5173 для разработки, домен на Vercel для продакшена), методы `GET` (и `POST`/`DELETE`, если будет общая очередь).
- **HTTPS** на продакшене (страница на Vercel открывается по HTTPS, HTTP-запросы браузер заблокирует).
- **Сжатие** gzip/brotli и заголовки кэша для `/cells`, `/meta` (данные меняются редко: `Cache-Control: max-age=3600` + `ETag`).
- **Время ответа** `/cells` — до ~1 с; фронт грузит его один раз за сессию.
- **Версионирование**: путь `/v1/…`; при смене полей — новая версия или новые необязательные поля, без переименования старых.
- **Авторизация**: фронт сейчас без логина. Если API закрыт, нужно договориться о способе (публичный ключ только для чтения, cookie или токен) — от этого зависит доработка фронта.
- **Числа**: десятичная точка, без строк вместо чисел; координаты WGS84 (EPSG:4326).
